# R5 - Node 执行适配与旧路径退役

状态: 未开始.

目标: Node Embedded 与 Node Plugin backend 消费相同完整编译产物, 并在
稳定后删除正则 TypeScript stripping.

## Node profile

- [ ] 实机验证并冻结 Node compiler profile revision.
- [ ] 使用显式 `module=NodeNext` 和 `moduleResolution=NodeNext`.
- [ ] `.mts/.cts/.ts` module kind 行为与文档一致.
- [ ] 处理相对 import 扩展名和 generated URI.
- [ ] 支持静态依赖和 dynamic import.
- [ ] 分别测试 `import(variable)`, CJS `require(variable)` 和生成扩展名映射.
- [ ] 支持 CJS 与 ESM.
- [ ] Node declarations 与 Rhino declarations 隔离.
- [ ] TypeScript target 与内嵌 Node 版本能力匹配.

## Backend

- [ ] Embedded backend 消费 `CompilationBundle`.
- [ ] Plugin backend 消费同一 bundle schema.
- [ ] 两种 backend 输出和 diagnostics 一致.
- [ ] Node Runtime plugin 只接收 JS, map 和 module metadata.
- [ ] 执行前 snapshot 中的加密模块以内存明文编译, 不落普通明文缓存.
- [ ] 运行中 late external TS 明确拒绝, 不启用隐式单文件编译.
- [ ] Node wrapper map 与 compiler map 组合.
- [ ] 同步和异步错误精确到 TS 文件, 行和列.

## 迁移

- [ ] 旧正则 stripper 先进入 legacy feature flag.
- [ ] 现有 lightweight TS 项目迁移到完整 compiler profile.
- [ ] 更新错误目录和项目向导.
- [ ] 删除 `NodeTypeScriptStripper`.
- [ ] 删除空 mappings 的原型验证.
- [ ] Node 插件缺失不影响 Rhino TypeScript 的回归门禁常驻 CI.

## 退出条件

- [ ] CJS, ESM, dynamic import 和多文件项目实机通过.
- [ ] Embedded/Plugin golden output 一致.
- [ ] 正式执行路径不存在 runtime type stripping.
- [ ] Node runtime stack 按 GA 契约精确到原 TS 文件, 行和列.
