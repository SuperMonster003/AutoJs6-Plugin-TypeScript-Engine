- `typescriptCompilerAvailable=false`；
- `typescriptProjectCompilation=false`；
- `typescriptSemanticDiagnostics=false`；
- `typescriptSourceMapV3=false`；
- `nodeRuntimeRequired=false`；
- ordinary production admission 继续为 **512 files、8 MiB/file、8 MiB total**；
- ordinary emitted output 为 **512 artifacts、512 KiB/JS、512 KiB/map、1 MiB total**，以
  `sourceMappingURL` rewrite 后的最终 packaged bytes 为 authority；
- frozen v1 AIDL/Binder transaction prefix 不修改，R2 扩展保持 additive；
- normal Release 不包含 TEST_ONLY private receipt、capacity scope 或 cleanup namespace；
- 不启用正则 stripping fallback，不改变 `backend=webview_worker`；
- evidence Debug/Release-equivalent 只能证明内部边界，不能替代 normal Release promotion。

任何 milestone 完成均不得隐式改变这些不变量；只有 M5 中对应的显式 capability gate
可以改变 capability metadata。

## R2 职责边界

### R2 负责

- compiler plugin 的 public discovery、Binder admission、ticket/ACK、cancel 和 callback；
- input snapshot、archive/config integrity、只读 file-backed VFS 与 compiler-owned
  module resolution；
- provisional Rhino CommonJS 与 provisional NodeNext compiler profile；
- structured diagnostics、JS/Source Map output、manifest、private staging 与 atomic commit；
- single-admission、deadline、Worker/process cleanup 与确定性 Release fault matrix；
- formal R2 request/output/diagnostic contract freeze；
- capability readiness 与向 R3 交付稳定 `CompilationBundle` contract。

### 由后续路线负责

| 责任 | 归属 | R2 交付边界 |
| --- | --- | --- |
| 编译失败时不创建 Rhino/Node 引擎、host routing 与 prepared source | [R3](R3.md) | R2 只返回稳定 terminal/output，不等待 host engine policy |
| Rhino target/runtime 兼容矩阵与运行栈行为 | [R4](R4.md) | R2 只交付 provisional Rhino profile 与可消费 bundle |
| Node runtime adapter、最终 Node profile revision 与旧 stripper 退役 | [R5](R5.md) | R2 实现 provisional NodeNext compile semantics，不等待 runtime adapter |
| actual LMK/OOM、长期 PSS/FD soak、性能 p95、缓存、完整安全压力矩阵 | [R6](R6.md) | R2 保留确定性 process/renderer failure 与 bounded cleanup gate |
| Beta 设备覆盖、升级/降级、发布索引、GA 宣称 | [R8](R8.md) | R2 只完成 compiler-service RC 与 capability contract |

这消除了旧路线中“R2 等待 public host 行为、R3 又等待 R2”的循环依赖，也避免与 R6
重复执行无限扩张的压力证明。

## 状态与验收规则

本路线只使用原子 checklist：

- `[x]` 表示该条文字所描述的实现、门禁和证据全部完成；
- `[ ]` 表示仍有工作，不用括号中的“部分已完成”掩盖状态；
- 下游或非 R2 项不进入 R2 分母，只通过上面的职责表移交；
- 每个新任务必须使用 `R2-M<里程碑>-<类别><序号>`，禁止继续新增“无编号 follow-up”；
- milestone 状态只由其固定 checklist 决定，不在完成后追加分母。

每个实现项遵循统一流程：

1. 先冻结 scope、输入输出和可判定的 Definition of Done；
2. 实现 unit/JVM 与 desktop golden；
3. 加入 source policy、APK/R8 和 frozen-contract gate；
4. 需要 private telemetry 时先运行 TEST_ONLY evidence Debug/Release-equivalent；
5. promotion-relevant 行必须再运行 normal Release API 24/35；
6. 审计 target crash/OOM/ANR/LMK、callback ordering、artifact hash 与 signer；
7. 更新 evidence 文档后才能勾选，失败探索与正式 PASS 分开记录。

- R4：Rhino runtime target 兼容、module loader、wrapper maps 与 stack mapping；
- R5：Node runtime CJS/ESM/dynamic import、最终 profile revision、旧 stripper 退役；
- R6：actual LMK/OOM、长期 soak、性能 p95、cache、runtime SourceMap registry 与完整
  security/privacy pressure suite；

如果延期项暴露 compiler-service contract 缺陷，必须回到对应 M2/M3 task 修复；不得
以“属于后续路线”为由忽略真实 contract blocker。
