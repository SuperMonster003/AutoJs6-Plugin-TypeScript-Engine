## 运行要求

- Android 7.0 / API 24 或更高版本。
- Chrome/WebView 119 或更高版本。API 24/25 镜像自带的旧 provider 不是支持
  基线；Android 系统版本满足要求并不代表 WebView provider 已满足要求。
- AutoJs6 6.8.0 Alpha7（build 5253）或更高兼容版本。
- Rhino `.ts/.tsx` 不需要 Node.js Runtime 插件；NodeNext `.mts/.cts` 与项目范围
  `.ts` 需要宿主安装并启用兼容的 Node.js Runtime 插件。

## 用户可见变化

- 同时开放 `compilerAvailable`、`projectCompilation`、
  `semanticDiagnostics` 与 `sourceMapV3`，capability mask 为 `15`。
- Rhino profile 支持 `.ts/.tsx`、多文件相对导入、JSON、UTF-8 路径、AutoJs6
  声明和原生 TSX UI DSL。
- NodeNext revision 2 支持 `.mts/.cts` 与具有明确 package boundary 的项目级
  `.ts`，按源码种类和 `package.json.type` 生成 `.mjs/.cjs/.js`。
- Node workspace 支持 `packages/<name>` 与 `packages/@scope/<name>` 子包各自声明
  `package.json.type`；普通 `.ts` 按最近 boundary 分别生成 ESM/CommonJS `.js`，根与
  每个子包继续禁止顶层 `scripts`。
- T2-1 将 Node 项目的 `node_modules` 作为独立只读 dependency layer 传输到插件私有
  immutable spool；lockfile 与 exact inventory 一起进入缓存身份，不占 4096 files /
  64 MiB ordinary caller 配额。T2-2 再将该层 framed 到 Worker，只读解析 bare/scoped
  package、子路径 `exports`、`types`/`import`/`require` 条件及 legacy entry fallback。
- Node ESM `.mts` 与根 `type: module` 下的 `.ts` 支持顶层 `await`；controlled
  tsconfig revision 4 可显式选择 ES2022 `target`/`lib`，NodeNext module identity 不变。
- Node ESM 入口与 dynamic `import()` 通过兼容 Node Runtime 的 V8 native linker 支持
  循环依赖、可变导出和 re-export live binding；四模块 `.mts` 图从 `initial=1` 更新为
  `updated=42`，CommonJS `require(esm)` 的同步互操作边界保持不变。
- controlled tsconfig revision 4 同时作用于 Rhino 与 NodeNext，开放 20 个 boolean
  选项、profile-scoped `target`/`lib` 与 snapshot-only `baseUrl`/`paths`；生成代码中的
  alias 会改写为显式相对运行时模块。revision 2/3 请求保持逐指纹兼容，其余结构性
  越界选项继续 fail closed。
- TypeScript 6 标准 Stage-3 类/方法装饰器在两个 profile 中默认可用，包含 typed
  `ClassDecoratorContext`/`ClassMethodDecoratorContext` 与 `addInitializer`；生成代码
  使用 `__esDecorate`/`__runInitializers`，无需新增 tsconfig 开关。
- AutoJs6 已接入执行前编译、可点击诊断、运行栈映射、多文件项目、动态 import、
  Tasker/定时入口和 APK Builder 的加密项目内存编译流程。
- AutoJs6 宿主的 TypeScript TSX 工厂、属性、事件、树与 XML 校验共 29 条运行时提示
  已移除 hardcoded English，并随应用语言覆盖 ar/en/es/fr/ja/ko/ru/zh-Hans/
  zh-Hant-HK/zh-Hant-TW；默认英语与显式英语资源保持完全一致。
- 跨执行缓存命中实测为 18–63 ms；普通 caller 输入 revision 3 上限为 4096 files、
  单文件 8 MiB、合计 64 MiB，普通输出上限为 512 artifacts、单个 JS/map 16 MiB、
  总计 64 MiB。
- 标准库 project ingress 改为 6-total/4-payload 有界 batching；固定 109-file workload
  从 97 降至 68 个 envelopes，576 KiB hard envelope 不变。

完整十语言变更记录见仓库根目录 `.changelog/CHANGELOG-*.md`。

## 已知边界

- 编译输入冻结在执行开始时的项目 snapshot；运行中出现的外部 TS 文件会被拒绝。
- npm bare/scoped package、子路径与 `exports` 从编译到执行共用 exact dependency layer。
  Rhino 装载 CommonJS/JSON 与 dual-package 的 `require` 分支，ESM-only package 返回稳定
  profile guidance；Node 使用不可变私有 workspace overlay 执行 ESM/CJS/dual package，且
  不回写依赖变更。workspace boundary 当前不解析 package `imports`；CommonJS
  `require(esm)` 保留同步互操作边界。
- caller 输入 revision 3 上限为 4096 files、单文件 8 MiB、合计 64 MiB；插件内置
  declarations 不占 caller 配额，revision 2 旧宿主的 512 files / 8 MiB 路径仍兼容。
- `baseUrl`/`paths` 只接受安全项目相对 pattern，并只解析执行开始时 snapshot 内的
  `.ts/.tsx/.mts/.cts`；绝对路径、`..`、wildcard 不匹配和 snapshot 外目标不会被读取。
  `outFile`、自定义 transformer/compiler plugin 等其余拓扑覆盖继续 fail closed。
- 标准装饰器无需配置。legacy `experimentalDecorators` 与 `emitDecoratorMetadata`
  当前产生 `910002` warning 后被忽略，不会改变 effective fingerprint，也不会生成
  reflect metadata。
- 顶层 `await` 只支持 Node ESM：`.mts` 或根 `type: module` 下的 `.ts`。`.cts` 与
  `type: commonjs` `.ts` 必须把异步流程放进 `async` 函数；插件不会静默切换 module kind。
- Node legacy TypeScript stripping 已由 Roadmap T6-1 完整删除：请求键、正则 erasure
  与 provider 私有明文准备协议均不存在；原始 `.ts/.mts/.cts` 直达运行时继续返回
  `ERR_AUTOJS6_TYPESCRIPT_COMPILER_REQUIRED`，snapshot/provider v3 只允许编译读取并仅
  交付 `.js/.mjs/.cjs` 执行。
